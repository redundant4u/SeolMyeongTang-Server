# Go 서버 테스트

`go.mod`의 Go 버전 이상이 필요합니다. `go/` 디렉터리에서 실행합니다.

- `go test -race ./...`: 전체 Go 테스트와 race detector를 실행합니다.
- `go test -race -covermode=atomic -coverpkg=./... -coverprofile=coverage.out ./...`:
  `main.go`를 포함한 전체 Go 소스의 문장 커버리지를 측정합니다.
- `go tool cover -func=coverage.out`: 전체 및 함수별 커버리지를 확인합니다.
  `go tool cover -html=coverage.out`으로 상세 결과를 볼 수 있습니다.
- `go vet ./...`: 정적 검사를 실행합니다.

세션 생성·조회·삭제·정원 제한·TTL·GC·검증·게시글 조회·환경 설정·라우팅을 검증합니다.
Kubernetes와 DynamoDB SDK는 실제로 실행하되 로컬 테스트 HTTP 서버를 사용하므로
실제 클러스터나 AWS 자격 증명이 필요하지 않습니다. 테스트 환경 파일은 임시 디렉터리에만 만듭니다.

전체 커버리지에 시작 코드와 프로세스를 종료하는 실패 경로도 포함하지만, 실제 서비스 시작과
원격 리소스 통합 동작까지 테스트했다는 의미는 아닙니다. `socket/` 서버는 이번 측정 범위에 포함하지 않습니다.

현재 코드에는 삭제 대상 소유권 확인보다 ConfigMap 삭제가 먼저 실행되는 문제와,
Pod 생성 실패 시 이미 만든 ConfigMap을 되돌리지 않는 문제가 있습니다. 기존 응답을 검증하는
테스트의 통과가 이 리소스 접근·정리 문제까지 해결했다는 뜻은 아닙니다. 이번에는 동작을 변경하지 않습니다.

로그 정제에도 `Authorization: Bearer <값>` 문자열의 값이 남는 결함이 있습니다. 세 문제 모두
로컬 진단 테스트로 재현했으며, 이 테스트 PR과 별도로 수정이 필요합니다. 정상 테스트는 실제로
정제되는 문자열의 결과를 확인하며, 문자열이 단순히 달라졌다는 이유만으로 성공 처리하지 않습니다.
